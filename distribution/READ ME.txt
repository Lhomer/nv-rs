nv-rs Windows preview
=====================

nv-rs runs Fallout: New Vegas from your own copy of the game, on the game's code translated to
Rust. This is a PREVIEW: Windows only, with bugs left. It has only been run on one PC so far, the
maintainer's, so your PC may turn up problems nobody has seen. Please tell us (see the end).

nv-rs is an independent project. It is not affiliated with, endorsed by or sponsored by Bethesda,
ZeniMax, Obsidian or Microsoft. This package has no game files in it. You need your own installed
Fallout: New Vegas, version 1.4.0.525 (the last update).


Start
-----
1. Extract the whole ZIP to a folder of its own that is NOT inside Documents, AppData, Program Files
   or the game's folder. For example C:\Games\nv-rs. It doesn't need administrator rights.
2. Double-click Launcher.exe. It looks for a newer build, then starts the game (Play.exe). From
   then on, start nv-rs with Launcher.exe (see "Updates" below); Play.exe still starts the game
   without looking.

Windows will probably warn you, because the program is new and not signed. See "If Windows or your
antivirus objects" below.

The first start finds your game (Steam, GOG, Epic, or it asks), checks its version, reads your
graphics card and sound device (about 20 seconds; a small window says what it is doing) and starts
the game. Later starts take a moment. When your graphics card, drivers, monitors, sound device,
Windows language or Windows version change, nv-rs notices and reads them again.

  Launcher.exe           gets the newest build (when you agree), then starts the game
  Play.exe               the game
  Play with mods.cmd     the game with the mods in the mods folder (see mods\READ ME.txt)
  Settings.cmd           window or borderless, resolution, anti-aliasing, field of view, game fixes,
                         frame limit and more (next start). Close the game first: the game writes
                         its own settings file again when you change an option in its menu, and that
                         can undo a choice saved while it runs
  Import my saves.cmd    copies your saves from Documents\My Games\FalloutNV. Those stay as they are

Use Exit Game in the game's menu to quit. Saves reach the disk within about 5 seconds of being made,
so wait a moment after saving before you close the window with its X.


Updates
-------
Launcher.exe keeps this folder up to date. Each time it starts it asks the project's GitHub page for
the newest build of this version of nv-rs (no GitHub account is needed). When there is one, it says
which and asks; Yes downloads it (about 33 MB), checks it against the checksum published with it,
and puts the new programs in place of the old ones, then starts the game. No, no newer build, or no
internet: the game you have starts as it is.

An update replaces nv-rs's own files only: Play.exe, Launcher.exe, the app folder, the .cmd and
settings files, this READ ME and the licences. The userdata folder is never touched: your saves,
Fallout.ini and FalloutPrefs.ini (and with them your settings), logs, reports and the mods' play
data stay exactly as they are, and so do the mods you put in the mods folder. A download that fails
or doesn't match its checksum changes nothing, and if putting the new files in place fails part of
the way, the old ones are put back, so the build you had still plays. Close the game before
updating; Launcher.exe says so if it is running.

So the ZIP is only needed once, for the first install (or to bring this folder, with its userdata,
to another PC). BUILD.txt says which build you have.


Your files
----------
nv-rs never writes to your game folder, your Documents or your AppData. Saves, settings, logs and
reports all stay in the userdata folder here. To go back to the original game, just start it: nothing
of it has changed. To remove nv-rs, delete this folder (your saves in userdata go with it).
Playing with mods links your game's files into userdata\modgame rather than copying them. A link is
another name for the same file, so if you uninstall the game while that folder is still here, the
disk space stays used until you delete the nv-rs folder too.

Your real saves are only read, and only when you run Import my saves.cmd. Saves you make here are in
userdata\game\Documents\My Games\FalloutNV\Saves. They are normal saves; nv-rs doesn't copy them back
for you.

The first start takes your settings from the game's own launcher if you have run it (it copies them,
and your real ones stay as they are). If not, it starts on the game's High preset at your desktop's
size. Settings.cmd and the game's own menu change them.

Either way the game starts in a borderless window that fills the screen. For the game's own window
instead, choose Window under Display mode in Settings.cmd. That is bBorderless=0 in Fallout.ini's
[nv-rs Display] section (Bug fixes, below, says where the file is). With 1, or with no such line,
the window is borderless.

The field of view, how wide the world is seen in play (70 to 120 degrees; 75 is the original's), has
a slider in the game's own menu: Settings, then Display, Field of View at the end of the list. It
sets the view of the world and of your arms and weapon to the same number. It changes both as soon
as you are back in the game, and it is kept for the next start. Settings.cmd has the same slider
(that one takes effect at the next start). Both set the game's own fDefaultWorldFOV and
fDefault1stPersonFOV in Fallout.ini's [Display] section, so each shows what the other saved; if the
two keys say different numbers there, saving in Settings.cmd makes the arms and weapon's the
world's. The slider in the game's menu comes with the fixes: with Vanilla the game's menu is the
original's, and Settings.cmd still has its slider.


Controls
--------
Keyboard and mouse, as in the original. The mouse always turns the view: no button needs to be held.
The right mouse button is the game's own (aim with a weapon out, block), and every key can be
changed in the game's Controls menu. While the game's window is in front, the mouse pointer is
hidden and kept in it; the game shows its own pointer in its menus (Esc, the Pip-Boy, dialogue).
Alt+Tab, or another window coming to the front, lets go of the mouse; clicking in the game's window,
or moving the mouse once it is back in front, takes it again.

For testing only: with the variable NV_MOUSE_LOOK=hold set before Play.exe starts (in a Command
Prompt: set NV_MOUSE_LOOK=hold, then Play.exe), the mouse pointer stays free and the view turns only
while the right mouse button is held, which then doesn't aim. This is not how the original plays.


Quick loot
----------
Look at a container or a body and a small panel shows to the right of the crosshair, above your
weapon: its name, your weight against what you can carry ("Wg 265/401"), and its items, five lines
at a time, each with the item's icon, its name and how many ("(13)"); a bar on the right shows where
you are when there are more. The panel is mostly see-through, so you can see the world behind it;
its words are white, and red when taking the items would be stealing. The game goes on while the
panel shows: it goes away when you look elsewhere, step out of reach or open any menu, and the
game's own "Search" prompt is hidden while it is up. The mouse wheel, or the Up and Down arrow keys,
move the marked line (the wheel doesn't zoom the camera while the panel shows).

The keys are on the panel's last line:
  E) Take       your Activate key (E unless you changed it) takes the marked item, the whole stack;
                one item a press, and holding it does nothing more.
  X) Take All   takes everything.
  R) Open       opens the game's own container menu, as the original does, for anything the panel
                doesn't do.

R is also Reload: while the panel shows, R opens the container and does not reload; look away and R
reloads as usual. If you have made R your Activate key, Activate keeps it and Open moves to your
Reload key (the panel shows which). If you have bound X, or the arrow keys, to one of the game's
controls, that control keeps them, and the panel shows only the keys that work. When taking is
stealing, the names show in red and Take reads Steal.

Taking follows the game's own rules: from a container someone owns, items are taken as stolen and
anyone who sees it reacts, as when you take them in the container menu. Locked containers,
containers and bodies with a script of their own (quest ones, often), ash piles and empty ones open
as in the original, and items lying on the ground, pickpocketing and companions are as in the
original too. Taking from the list does not play a container's lid animation.

Quick loot comes with the fixes: with Vanilla (Settings.cmd, Game fixes), Activate opens containers
as the original does. To keep the other fixes without it, find the line ;bQuickLoot=1 in
Fallout.ini's [nv-rs Fixes] section and make it bQuickLoot=0 (without the ;).


Compact menus
-------------
The conversation, container, barter, inventory, repair and crafting menus use the game's smaller
font instead of its large console-sized one, so their lists show more lines in the same space
(more dialogue topics, more items when you trade or loot) and long names wrap less. The menus,
their options, items, prices and keys are the same; the HUD and the rest of the Pip-Boy are as
before. To go back to the large text, make the line ;bCompactMenus=1 in Fallout.ini's
[nv-rs Fixes] section bCompactMenus=0 (without the ;); Vanilla (Settings.cmd, Game fixes) turns it
off with the other changes.


Bug fixes
---------
Bug fixes are on by default. With them, the frame rate isn't held to the original's limit, the game's
time keeps pace with real time at high frame rates (the original runs fast there), and your character
lands on the floor after a jump instead of hovering a little above it. Menus run at up to 120 frames a
second (loading screens as fast as they can), and a dragged body is pulled as hard at any frame rate.

One change is not a bug fix but a choice of how to play: with the fixes on, you get a perk at every
level, not every second level as in the original. It counts from your next level-up, in new and old
saves alike (levels you already gained are not made up for), and a mod that sets its own
iLevelsPerPerk keeps its value. Vanilla gives a perk every second level, as the original does; to
keep the other fixes and still get a perk every second level, find the line ;bPerkEveryLevel=1 in
Fallout.ini's [nv-rs Fixes] section and make it bPerkEveryLevel=0 (without the ;).

To play the original game's behaviour instead, open Settings.cmd and choose "Vanilla (the original
game)" under Game fixes. Settings.cmd can also set a frame limit (60, 120, 144 and so on) or no limit,
which is the default, and a frame limit in menus (120 unless you choose another, or none). The frame
limits only work with the fixes on. Settings.cmd keeps them in the game's own Fallout.ini, in
userdata\game\Documents\My Games\FalloutNV (and the same under userdata\mods), in sections named
[nv-rs ...] (usually at the top of the file): sPreset=fixes or vanilla, iFrameLimit=0 (no limit) or a number, iMenuFrameLimit=120,
0 or a number. You can change them there too; a note above each line says what it does.


Game threads
------------
The game's threads (the main one, the AI, loading and sound) run side by side on your processor's
cores, as in the original. If the game misbehaves in a way it didn't with the previous preview (it
stops, hangs, or something acts oddly), open Settings.cmd, choose "One at a time (slower)" under Game
threads, and please tell us. Settings.cmd keeps that choice in Fallout.ini as bSteppedThreads=1;
with 0 the threads run side by side.

The game's drawing is handed to a thread of its own (the original draws on its main thread), which
makes busy places faster. If something looks wrong or the game stops in a way it didn't with the
previous preview, open Settings.cmd, choose "Main thread (slower)" under Drawing thread, and please
tell us. Settings.cmd keeps that choice in Fallout.ini as bRenderThread=0; with 1 the drawing has its
own thread.


Renderer
--------
The game draws on Vulkan (on a graphics card without Vulkan, on Direct3D 12), with the original's
shaders and look. If something looks wrong or the game stops while drawing in a way it didn't with
the previous preview, open Settings.cmd, choose "Direct3D 9 (the original's)" under Renderer, and
please tell us. Settings.cmd keeps that choice in Fallout.ini as sRenderer=d3d9; with sRenderer=vulkan,
or with no such line, the game draws on Vulkan. Where neither Vulkan nor Direct3D 12 can draw, the
game draws with Direct3D 9 by itself.


What works
----------
The whole game runs on its translated code: the opening, the open world, quests, combat, V.A.T.S.,
the Pip-Boy, saves and the DLCs, with the original graphics (drawn on Vulkan) and sound (through your
own DirectX).
Regular .esp and .esm mods work.


What doesn't yet
----------------
- Mods that need xNVSE, JIP or other plugins (.dll files) don't work yet.
- Controllers don't work yet: keyboard and mouse only.
- It is slower than the original. On the maintainer's PC (a laptop with an RTX 5070 Ti, at 2560x1440
  with 8x anti-aliasing), with the bug fixes on, about 103 frames a second in Doc Mitchell's house and
  about 44 in Goodsprings. The original runs at about 120 in Doc's house. Your numbers will differ.
- Memory: the game's code still has the original's 4 GB limit, about 3.2 GB of it for the game's own
  use. A very heavy mod list can run out, as in the original. Removing this limit is planned.
- Known bugs: fitting a second weapon mod can stop the game. Sound can crackle when frames are slow.
  Some settings may not change anything. There are others we don't know about.
- A Steam, GOG or Epic overlay, achievements and the game's launcher are not used.
- Not tested yet, because they have only one PC to run on: other graphics cards (AMD, Intel, older
  NVIDIA), sound set to anything but 7.1 or stereo, GOG and Epic copies, languages other than English,
  Windows 10. GOG, Epic and some regional copies may be refused, with a message that says so.


Problems at the start
---------------------
When nv-rs can't start it says why in a window, for example: no game found; the wrong version of the
game; DirectX's d3dx9_38.dll missing (install "DirectX End-User Runtimes (June 2010)" from Microsoft);
the folder's path too long or in a place it shouldn't be. With no sound device the game starts silently.
Everything it said is in userdata\logs\launcher.log.


If Windows or your antivirus objects
------------------------------------
The programs here are not signed, and few people have run them, so:
- Windows SmartScreen may say "Windows protected your PC". Click "More info", then "Run anyway",
  once you have decided you trust this download.
- On Windows 11 with Smart App Control turned on, unsigned programs are blocked and there is no such
  button. nv-rs can't run on such a PC without turning that off, and we don't ask you to.
- An antivirus may stop or remove Play.exe or app\FalloutNV.exe, because they are new and start other
  programs. Download only from the project's own page. Compare the ZIP's SHA256 with the one published
  with it. The source for every file is at https://github.com/slaterain/nv-rs (BUILD.txt names the exact
  version).
Don't turn off your security software for this.

app\FalloutNV.exe is nv-rs's own program, not the game's. It has that name because NVIDIA's driver fixes
and Windows' sound settings for the game go by the name.


Reporting a problem
-------------------
https://github.com/slaterain/nv-rs/issues

Press F12 in the game when you see something wrong. You hear a beep, and a numbered folder appears
in userdata\reports with a picture and the log so far. Add your words to its note.txt and attach the
folder, zipped. If the game stopped, attach the newest game-*.log from userdata\logs, and launcher.log.
Say what you did just before, and your graphics card, Windows version and game store.

Logs can show your Windows user name in folder paths: look through them first if that matters to you.
Never attach game files. Please compare with the original game when you can: if it behaves the same
there, it isn't an nv-rs bug.
